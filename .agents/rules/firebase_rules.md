# Firebase 安全規則與資料庫架構變更守則

**這是一條對所有未來協助本專案的 AI 助手生效的強烈提醒！**

## 🛑 絕對不可重蹈覆轍的血淚教訓
在過去的開發經驗中，我們曾發生過以下嚴重事故：
- **背景**：為了進行資料庫瘦身（解決 Payload Too Large 的問題），AI 將部分巨大資料（如機構公印 Base64 字串）從舊的 `organizations` 集合抽出，並建立了一個名為 `org_assets` 的新集合。
- **事故**：AI 修改了前端程式碼，加入了讀寫新集合的邏輯，**卻忘記同步修改 Firebase 的 `firestore.rules` (安全規則)**。
- **後果**：當管理員登入時，前端對新集合的讀寫請求被 Firebase 安全防火牆預設擋下，拋出 `Missing or insufficient permissions` 錯誤。由於前端的 API 請求失敗，導致整個畫面呈現**一片空白**、資料完全無法載入。
- **瞎忙**：由於未能在第一時間察覺是 Firebase 規則的問題，AI 浪費了大量的時間在猜測是否為「資料量過大」、「程式碼語法錯誤」、「分批載入邏輯錯誤」，繞了一大圈才發現只是安全規則未放行。

## 📝 給 AI 助手的強制工作規範

為了避免這個狀況再次發生，**如果你在本次對話中需要「新增 Firestore Collection」、「更改集合的讀寫權限」或是「新增子集合」**，你必須嚴格遵守以下步驟：

1. **同步更新規則檔**：你必須主動且立刻去修改專案根目錄下的 `firestore.rules`，將新集合的讀寫規則 (`allow read, write: ...`) 加入其中。
2. **務必主動提醒使用者**：修改完 `firestore.rules` 之後，你必須在回覆使用者的訊息中，用**強烈且明顯的語氣**提醒使用者：「我們已經新增了資料庫集合，為了避免畫面空白與權限錯誤，**請務必前往 Firebase Console 後台，將最新的 `firestore.rules` 內容貼上並發布！**」
3. **遇到錯誤先查權限**：如果使用者回報「畫面空白」、「資料消失」或丟出 `Missing or insufficient permissions`，**第一時間請檢查 `firestore.rules`**，絕對不要先去懷疑資料量或語法，請優先確認權限是否有正確放行！

請所有接手的 AI 助手將這段守則銘記在心。
